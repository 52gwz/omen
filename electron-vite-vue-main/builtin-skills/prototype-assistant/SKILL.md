# 原型助手

## 目标

创建用于讨论和验证的 HTML 原型，而不是生产级 UI。

## 默认规则

- 原型项目根目录命名为 `用户项目名称_prototype`。
- 如果用户没有明确给出项目名称，先从上下文推断；仍无法确定时，最多只问一次。
- 在原型项目根目录创建 `index.md`，用于说明页面之间的连接关系和每个页面的简要功能。
- 每个原型页面都必须有独立文件夹，页面资源和说明文档放在该文件夹内。
- 每个页面文件夹都必须有一个页面原型 `.html` 文件和一个对应的 `.md` 说明文档。
- 除非用户明确要求更多内容，否则每个页面只输出一个自包含的 `.html` 文件。
- 只使用内联 `<style>`，不要引入框架或构建步骤。
- 保持低保真页面风格：灰度、边框、留白、占位块、简短标签。
- 使用系统字体和基础 CSS。
- 优先使用语义化区域：`header`、`aside`、`main`、`section`、`footer`。
- 使用简短的示意文案和少量样例数据。

## 目录规范

推荐使用以下结构：

```text
项目名_prototype/
  index.md
  page-home/
    index.html
    page.md
  page-detail/
    index.html
    page.md
```

- 页面文件夹名使用清晰、稳定、可读的英文或拼音短名，优先加 `page-` 前缀。
- 页面 HTML 默认命名为 `index.html`。
- 页面说明文档默认命名为 `page.md`。
- `index.md` 维护全局导航关系。
- `page.md` 维护单页目标、核心模块、主要交互和入口/出口关系。

## 风格规则

- 默认把每个请求都当作线框稿来处理。
- 优先使用黑、白、灰，除非用户明确要求，否则不要使用品牌色。
- 图片用空白方框或带标签的占位块表示。
- 图表、地图、媒体区域统一用带边框的占位块表示。
- 避免精致化视觉：渐变、阴影、玻璃质感、大圆角、复杂图标、丰富插画。
- 聚焦结构、层级、留白和交互状态。

## Token 规则

- 最多只问一个澄清问题，而且仅在页面类型不明确时才问。
- 如果需求不完整，直接采用合理默认值继续。
- 除非用户要求，否则不要生成多个版本。
- 不要在代码前后附加冗长说明。
- 保持 CSS 紧凑且可复用。
- 保持 DOM 层级尽量浅。
- 文档说明保持简短，优先使用短列表，不写长篇设计说明。

## 工作流程

1. 确定原型项目名称，并创建 `项目名_prototype` 根目录。
2. 创建或更新根目录 `index.md`，记录页面列表、页面跳转关系和页面简要功能。
3. 为每个页面创建独立文件夹，并放入 `index.html` 与 `page.md`。
4. 推断页面目标和主要用户动作，先用大布局块搭出整体结构。
5. 只添加表达流程所必需的最少控件和示例内容。
6. 确保结果可以直接在浏览器中打开。
7. 如果是修改现有原型，必须同步更新对应页面的 `page.md`，如果页面关系有变化，也必须同步更新根目录 `index.md`。

## 文档同步规则

- 创建新页面时，必须同时创建该页面的 `index.html` 和 `page.md`，并更新根目录 `index.md`。
- 修改页面原型时，必须同步检查并更新该页面的 `page.md`。
- 如果页面名称、页面职责、页面入口、页面出口、跳转路径或页面状态发生变化，必须同步更新根目录 `index.md`。
- 不允许只改 HTML 不改文档；文档必须与当前原型保持一致。

## 文档模板

根目录 `index.md` 应至少包含：

- 原型项目名称
- 页面清单
- 页面之间的跳转/连接关系
- 每个页面的一句话功能说明

页面目录下的 `page.md` 应至少包含：

- 页面名称
- 页面目标
- 主要模块
- 主要交互
- 页面入口
- 页面出口

## 不适用场景

- 不要把这个 skill 用于高保真视觉设计。
- 不要把这个 skill 用于生产可用的前端架构实现。
- 除非用户明确要求，否则不要加入动画或复杂组件系统。
